Looki用了四个多月，但我反而希望它砍掉一些功能。哈哈哈。

Looki有个联合创始人做过自动驾驶。他讲这款产品时，逻辑也很像自动驾驶：先感知环境，再做决策。如果一个设备一直挂在胸前，它就能看见日常生活，然后替你记录、判断、提醒。按他的说法，物理世界本身就是最好的 prompt。

这个故事听起来很顺。后来越用越觉得，它可能没必要把“感知→决策”整条链都吃下来。它真正有优势的，其实只是前半段。

## 三种产品，三种节奏

早期的 Looki 很像三个产品挤在一个 App 里：会自动剪 Vlog、画漫画，像内容工具；会生成日记、保存片段，像第二大脑；又把自己讲成一个会主动提醒、能跟人对话的 agent。

但三个定位，其实有点打架。剪一段 Vlog，晚几分钟没关系，重点是成品好不好；做第二大脑，重点是东西能不能存下来，以后还找得到；主动提醒却必须快，等事情过去了再开口，基本等于没说。

Looki 在设备端只是间隔采样，拍到的内容传到云端后才会被理解。这条路线省电，也更现实，用来回看一天或者整理素材都没什么问题。但要它一直知道当下发生了什么，并且马上做出反应，就有点勉强了。

旧版 App 又把这种别扭放大了一遍。四个 tab 各放着一条信息流，彼此又不相通；看过的东西很难再找回来，对话也是问一句就断。日记写错了，我没法顺手告诉它哪里错；片子没剪到重点，也不能接着让它重剪。用起来不像在和一个 agent 对话，更像它隔一阵交一份作业，交完就走。

最近Looki App的改版，终于修复了统一信息流的问题，也终于可以连续追问了。

## 记录不等于记忆

但另一层暴露的更彻底。我现在能搜索 Looki 记录过什么，却还是看不见它根据这些记录形成了什么判断。前者是记录，后者才是 memory。如果它把一次例外当成了我的习惯，或者把一件事认错了，我应该能看见，也应该能直接改。记忆不是给高级用户准备的设置，它就是这个产品以后所有判断的地基。

改版以后，我反而不再纠结怎么把 Looki 做得更像 agent 了。搜索和连续对话补上以后，它更像一个可以查询的记录库；但 App 变顺了，不代表设备就能更快地理解眼前正在发生的事。这也让我更确定：与其逼它负责最后的判断，不如先把感知做好。

## 我需要的是观察

我不太需要它把生活包装成更多日记和高光。日常本来就没那么多新鲜事，每天又吃了一顿饭、又坐在电脑前几个小时，别说别人，未来的我大概率也懒得翻。我也不太指望它主动提醒我：有明确需求时，我会主动打开 App；等它自己发现，很多时候已经晚了。

我真正需要的，是另一种更无聊的东西：观察。

这里的观察不是一天到晚录像，也不是每天生成一篇“今天过得很充实”。它只需要把平时看到的零碎片段慢慢攒起来。今天九点吃晚饭，没什么可说的；连续一个月都在九点以后吃，才说明作息可能变了。某天没运动也不说明什么；连续几周的实际活动量都比我以为的少，这才是一条有用的信息。一次外食很普通，放到一个月里，可能就能看出我最近是不是越来越懒得做饭。

单条记录没人想看，积累起来却能慢慢拼出一个人实际上是怎么生活的。这刚好更适合 Looki 现在的工作方式：间隔采样可以，晚一点处理也可以，偶尔漏掉一段通常不致命。

## 可见、可改，也可带走

不过，不要求它实时反应，不等于可以随便猜。它观察到了什么、事情发生在什么时候、它有多确定、依据是哪段原始记录、我后来有没有纠正过，这些都应该留下来。否则误判越积越多，只会越来越难收拾。原始视频可以藏起来，免得界面太乱；它对我的理解不能藏。

真正有用的定制，也不是多配几条喝水提醒。我应该能告诉它：帮我留意外食、运动和通勤，别的先不用管。然后这些观察最好能拿出来，交给我自己选择的 agent，而不是永远锁在 Looki 的 App 里。

## 把屏幕外的生活交给 agent

我已经把时间、任务和财务数据同步进自己的 vault。每次让 agent 给建议之前，我会先让它看看我最近到底做了什么，而不是只听我当下怎么描述自己。但这里一直缺一块：屏幕外的生活。它知道我安排了运动，却不知道我最后有没有出门；知道今天开了几个会，却不知道下班以后是不是又在电脑前坐了四个小时。

Looki 刚好可以补上这一块。它只要把这些观察留下来，再交给更适合做判断的 agent 就够了。

我之前觉得，Looki 把 agent 讲得最响，却偏偏最难把这部分做好。现在看，这一步可能根本不用它来做。这样甚至能节约不少AI算力（钱！）

Agent 不一定要挂在胸口。眼睛才需要。
