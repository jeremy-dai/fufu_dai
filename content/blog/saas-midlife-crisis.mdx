刚从 SaaStr 回来，最大的感受就是，全在卷 agent，卷得特别没创意，姿势出奇地一致——都不肯让用户出圈。

但不是怕用户流失。而是怕用户每出去溜达一趟，自己家 agent 就少看一段信息，就傻一截。把人留住，现在不是怕他跑了不续费，是要喂 context。

## 把用户留住，就是给 agent 喂饱

所以你看吧，各家 app 都跟吃了膨大剂似的，营销也做，客服也做，数据看板也做，工具集成也做，恨不得把你一天八小时全吞进去。听着像产品扩张，骨子里就是 agent 的食欲。它得看着你，看得越多，话才说得像样。

我们自己用 agent 也是这个感受。能塞进一个 repo 的，或者留在一个系统的，绝对不拆开。拆开了工程上其实更干净，边界清晰，职责单一，所有教科书都教你这么干。但是 agent 它不懂这个。它不知道隔壁项目里有个现成的 helper，不知道你上周才定义过这个类型，每次都给你重新发明一遍轮子。整洁是给人看的，agent 不认这套，它认的就是一锅端。

之前写过一句话，叫"约束工程大于能力释放"。Agent 的聪明劲儿，天花板不在模型，在它能看见多少。同一个 Claude，你从头开始，跟给它相关的记忆，出来的东西完全是两种生物。我后来干了一个特变态的事儿——把自己的时间数据、财务流水全同步到一个 vault 里，每次让 agent 开口前，先让它读读我最近过得怎么样。

SaaS 厂商现在算盘打得我都听见响了：把人留住，就是把数据留住；把数据留住，就是给 agent 喂饱；agent 喂饱了，才能把人继续留住。一个闭环，完美。

## 可大部分 SaaS 撑不起这个闭环

问题是，这闭环真玩得起的，一只手数得过来。要做个完整的 agent，你得有足够的流量，足够杂的场景，在用户心里得有那个位子。大部分垂直 SaaS 哪够呀，用户一天就打开你二十分钟。硬憋出来一个 agent 上线，跑一个月，DAU 还没你们官网那个"联系我们"按钮的点击量高。

按理说到这一步，答案挺清楚的——你费老劲做不成完整的 agent，那就去给人家当接口呗。把自己变成个插座，让真正的大 agent 来接上你，调你。流量是人家的，数据是人家的，但你就赚个工具费，体体面面。多好。

## 当接口，比死还难受

可没几家乐意。为啥呢？因为当了接口，你跟用户那根弦就彻底断了。以后用户跟 agent 聊着天，agent 替你点了你的服务，你连用户长什么样都看不见。这对天天盯着"用户增长曲线"的 SaaS CEO 来说，比杀了他还难受。那感觉，哎，就是特别没劲。

所以就卡在那。往上，做不成整个的 agent；往下，又不肯老老实实当个插口。手里这套产品，越来越像个中年人——上面的位置爬不上去，下面的活儿又拉不下脸来干。

## 二十年转了一圈，又回到原点

最逗的是，二十年前 SaaS 这玩意儿刚起来的时候，最酷的故事就是"做小做精，让别人用 API 调你"。现在真轮到别人调自己了，一个个倒觉得委屈了。荒诞吧。
